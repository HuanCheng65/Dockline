# 实时状态（Live Status）功能设计

状态：讨论定稿 2026-08-24；2026-08-25 与实现侧核对后修订
适用范围：Dock 替代项目的实时状态子系统。基础设计（底部窗口条、每窗口一个 slot、v3.1 定稿）见项目主计划文档。

---

## 1. 定位

这个功能的本职是注意力路由：后台任务干活时把你隔离出去，需要你的那一刻把你精确拉回来。进度展示、播放信息等属于附带能力，设计冲突时以注意力路由优先。

有价值的场景：

1. AI agent 会话（Claude Code 等）—— 专用模块，价值最高
2. 终端长命令（编译、测试、rsync）—— 通用观测
3. 媒体播放 —— 专用模块
4. 实验/训练监控 —— 走通用上报协议，脚本自己 curl
5. 下载/文件拷贝 —— NSProgress + FSEvents，后置

**第一版做 1 与 3。** 取的不是价值排序，是设计覆盖面：agent 压的是等待态与一次性事件，媒体压的是常驻文本与点缀层，两个模块正好把下一节那两层各撑开一半。终端长命令与 agent 是同一个形状（在跑 → 完成 / 失败），进第一版只增加工作量，不增加要验证的东西，因此后置。已知代价：媒体是第一版里唯一一块新基础设施（见第 5 节的跳板方案），大概率也是先出问题的那个。

状态来源分两档：简单任务只有「在跑 / 完成 / 失败」三态，走通用协议；vibe coding 这类有对话、有决策交互的场景写专用模块，不受通用协议约束。两档只在渲染层汇合。

## 2. 宪法：slot 分层模型

这是整个功能的最高规则，后续所有状态源接入都用它裁决，不逐 case 讨论。

一个 slot 分两层：

**身份层 —— 任何状态源不得改写。** 包含三样：

- 位置：slot 在条上的位置永远不因状态变化移动
- 图标：App 图标永远不被替换（角标、点缀可以叠加，见下）
- 点击语义：左键点击永远是召回窗口，全条统一，无特例

身份层服务肌肉记忆和视觉搜索，价值来自稳定。图标换成专辑封面、slot 变成内嵌播放器，均属违宪。

**状态层 —— 状态源可以改写。** 包含两部分：

- 文本层：slot 的文字标签。定稿设计里它本来就是易变的（歧义时显示窗口标题），实时状态只是新增内容来源。同一时间按优先级栈取最高项显示：
  1. 常驻状态文字（歌名一类）
  2. 窗口标题（仅歧义时）
  3. 空

  **等待态与终态的文字不进文本层，走胶囊。** 原先的栈把等待态文字排在最上，代价落在宽度上：单窗口的 App 文本层宽度为零，塞进「待授权」会让格子从零长到约 40pt，把右侧整排推开——而 agent 请求授权是高频事件，格子一变宽就推挤邻格，正是身份层要保的东西。胶囊本就把同一个词放大显示在它头顶，格子里再写一遍既冗余，又要付这个代价。留在文本层的只有常驻型，它更换频率低，现有 6pt 的宽度迟滞足以挡住抖动。
- 点缀层：叠加在图标上或图标旁的小元素——状态点、进度环、声波纹、角标。专辑封面允许以角标形式出现（图标角落小圆图），主图标不动。

## 3. 显著度分级：谁在等谁

显示强度由「此刻谁在等谁」决定，三档：

**它在干活，你不用管（working）**
唯一需要传达的是「还活着」。静息态只给低调呼吸动效点，不给文字——文字诱导阅读，阅读即打断。当前动作细节全部收进 hover。

**它在等你（waiting）**
唯一允许高显著度的状态。slot 浮出胶囊，常驻不衰减，颜色与其他状态明确区分，一个词说明等什么。多会话同时等待时按先来后到排队，同屏只弹一个胶囊，其余在 hover 卡中排队。

**它停了（done / failed / rate-limited）**
一次性事件，做成「未读」语义：✓ 或 ✗ 加一行摘要，停留到用户点击或跳回过对应窗口为止，再退场。被限额是独立状态（含义与完成相反），可附重置倒计时。

进度的口径定死为两半，免得后面每接一个状态源重问一次：**有确定进度时，格子边缘走进度环**——它属于点缀层，显著度本来就低，不构成打断，也是主计划文档 §3 的既定表达；**文字型进度（任务 3/7、耗时、ETA）只在 hover 中出现**，永远不主动争取注意力。

胶囊的呈现方式：向上浮出 overlay，而非在条内横向扩展。横向扩展会推挤相邻 slot 位置，违反身份层的位置稳定规则。

决策放在哪做，由决策大小决定：

- 小决策（选项式）就地在胶囊/卡片里完成：agent 提问四选一、展示完整命令的允许/拒绝
- 大决策（需要读代码、读完整计划）胶囊只提供一键跳转到对应窗口，不塞进小卡片

## 4. Vibe coding 模块（Claude Code）

### 4.1 数据链路

Claude Code hooks 支持五种 handler 类型（`command` / `http` / `mcp_tool` / `prompt` / `agent`），其中 `http` 让 hook 直接把事件 JSON POST 到本地 URL。daemon 开本地 HTTP 端口，安装时向 `~/.claude/settings.json` 合并写入 hooks 配置（注意 merge 不覆盖）。hooks 在终端、IDE 插件、桌面 App 中触发相同事件。

**但不能全走 http。** hook 的公共字段里没有进程号（逐字核对过：`session_id`、`prompt_id`、`transcript_path`、`cwd`、`permission_mode`、`effort`、`hook_event_name`）。http handler 又没有子进程，于是两件事同时落空：拿不到进程树就**不知道宿主 App 是谁**，拿不到 pid 就**没有存活信号**——而 `SessionEnd` 只在正常终止时发，agent 崩掉时什么都不发。

因此按频次分工：

- **`command`** 只挂 `SessionStart` 与 `UserPromptSubmit`。它是 claude 的子进程，爬得到宿主 App，也拿得到 claude 的 pid 用来盯存活。这两个事件低频，每次一个进程启动的代价可以忽略。
- **`http`** 挂其余高频事件（`PreToolUse` / `PostToolUse` / `Notification` / `Stop` / `TaskCompleted` 等）。到那时会话已经绑好，只需更新状态。

会话消失有两个来源，都要接：正常终止走 `SessionEnd`，异常消失靠盯 `command` hook 报上来的那个 pid。不设超时——「多久算没动静」只有上报方知道，替它猜只会让长任务的指示器中途消失。

### 4.2 事件映射

| 事件 | 用途 |
|---|---|
| SessionStart / SessionEnd | 会话状态的创建与移除 |
| UserPromptSubmit | 进入 working |
| PreToolUse / PostToolUse | 更新当前动作描述 |
| PermissionRequest | 权限决策，hook 返回 decision.behavior（allow/deny）实现远程批准 |
| Notification（matcher: permission_prompt / idle_prompt / agent_needs_input / agent_completed） | 各类等待信号 |
| AskUserQuestion（经 PreToolUse 拦截） | 选项式提问，就地作答 |
| ExitPlanMode（**它是工具名不是事件名**，同样经 PreToolUse 拦截） | 计划审阅，跳转窗口处理 |
| TaskCreated / TaskCompleted | 任务清单进度（n/m） |
| SubagentStart / SubagentStop | 并行子 agent 数量 |
| Stop | 完成，last_assistant_message 字段截一句做摘要 |
| StopFailure | 轮次因 API 错误结束，带 `error_type` / `error_message`——失败与限额靠它区分 |
| PermissionDenied | auto 模式自动拒绝的记录：本该问你、被规则挡掉了 |
| Elicitation / ElicitationResult | MCP 向用户要输入，同属「在等你」 |
| CwdChanged（带 `new_cwd`） | 会话换了工作目录，直接喂给 4.3 的窗口匹配 |
| TeammateIdle | 又一路空闲 / 等待信号 |
| Notification（matcher: quota_auto_resume_fired / _stale / _disabled） | 限额相关，供第 7 节的全局区 |

事件输入自带 permission_mode 字段，可判断会话是否 auto 模式。auto 模式下逐条批准基本消失，「需要你」的时刻集中在：agent 提问、计划审阅、未被规则覆盖的权限、完成、限额。设计以这几类为主，逐条批准为辅。

transcript JSONL（hook 提供路径）做 tail 补充细节：当前文件、命令、耗时。**但它是异步写的，会落后于内存里的对话**，当前轮的最后一句话要用 `Stop` / `SubagentStop` 自带的 `last_assistant_message`，不要去 transcript 里捞。

### 4.3 会话 → 窗口映射

会话键直接用 hook 自带的 `session_id`，不必另造——它在每个事件里都有。要解的只剩「这个会话住在哪扇窗口」。

- 独立终端（Ghostty、iTerm 等）：进程树直接爬到窗口
- VS Code：pty host 是共享进程，**爬得到 App、爬不到窗口**。实测链路 `zsh ← claude ← fish ← Code Helper ← Code`；Code Helper 虽有自己的 bundle ID 且是 LSUIElement，但未在 `NSRunningApplication` 注册，不会把上报误停在它身上。主路是用 `cwd` 末段匹配窗口 AXTitle——VS Code 默认标题的尾段就是工作区文件夹名，而 `cwd` 每个事件都带，`CwdChanged` 负责保鲜
- **前台焦点只当同分候选之间的裁判，不许翻案。** 仅当 cwd 匹配出多个候选时才用它，且焦点窗口必须是候选之一，否则忽略。理由是失败的形状不同：cwd 匹配失败是**歧义**，当场就知道有几个候选对得上，可以拒绝绑定；而「取上报那一刻的前台焦点窗口」失败是**静默绑错且无界**，可能绑到另一个 App 的窗口上。它还恰好踩在这个功能存在的理由上——你提交完就切走，hook 到达时读到的焦点已经是你切过去的那扇
- 匹配不上、或候选里没有焦点：不绑，退回 App 级（即现在的行为），并给一个一次性认领的入口
- 认领**暂不跨重启持久化**。那需要一个跨重启稳定的窗口身份，是主计划文档里单列的 spike；第一版的绑定只在会话内，重启后下一次提交 prompt 即重新绑上
- 同窗口多 session：slot 显示最高优先级状态（waiting > working），hover 展开列出全部

### 4.4 交互

等待四档的文案取同一句式起头：**待回答 / 待授权 / 待审阅 / 待输入**。它们是并列的等待，差别只在等什么，句式一致才读得快。终态在上报方未给摘要时缺省为「✓ 已完成」「✗ 已失败」「◷ 已限额」——只留一个记号的话，看得见结果却读不出是什么结果。

- working：呼吸点，无文字
- 提问：胶囊「待回答」，展开列选项按钮，点击经 hook 回传答案
- 权限：胶囊「待授权」，展开显示完整命令。**第一版只提供跳回窗口，不在胶囊里直接允许 / 拒绝**——「允许执行这条命令」摆在一个不需要焦点的浮层上，误点的代价比这个功能里其他任何操作都高，这也正落在本节「大决策跳转」那条规则里。日后若开放就地批准，命令全文必须展示，避免盲批
- 审计划：胶囊「待审阅」，点击跳转窗口
- 完成：✓ + 摘要一句，未读语义
- 限额：独立状态色 + 重置倒计时

## 5. 媒体模块

数据源：MediaRemote 私有框架（歌名、封面、播放状态、控制指令、来源 bundle ID）。macOS 15.4 起需走 mediaremote-adapter 跳板方案（借系统带授权二进制），社区方案成熟。

- 静息：音源 App slot 图标角上声波动效（标识声音来源，类似浏览器标签小喇叭）；封面以角标形式叠加图标角落；歌名占用文本层常驻显示，超宽截断。提供开关：「常驻 / 仅切歌时显示几秒」，默认常驻
- 切歌瞬间：文本淡出淡入作为切换确认
- hover：小卡 = 封面 + 歌名/歌手 + 上一首/暂停/下一首（Windows 任务栏预览形态）
- 点击：slot 左键仍是召回窗口，控制键只在 hover 卡内。播放控制不改变点击语义

## 6. 通用观测（终端长命令）

- 首选：注入 precmd / preexec，**直接调用上报命令**。原方案是让它发 FinalTerm 语义序列（OSC 133），但我们不是终端、读不到 OSC 序列，那条路还得再借终端自己的 API 绕回来；同一个注入点直接上报，不需要任何终端配合，覆盖面反而是所有 shell。代价是每条命令多一次进程启动（量级几毫秒），需实测
- 不做：轮询子进程、按已知长任务进程名识别。那是按名字猜，与主计划文档 §9 对注意力弹跳的裁决同一条口径——宁可缺这个功能，也不用启发式去猜
- 后置：NSProgress 文件订阅（Progress.addSubscriber(forFileURL:)，需对方发布且已知路径，配合 FSEvents 发现新文件）；AX 读窗口内 AXProgressIndicator，逐 App 适配按需做

三态：在跑（进度环）→ 完成 ✓ / 失败 ✗（未读语义）。

## 7. 全局区

Claude 限额（5 小时窗口 / 每周上限）是全局资源，不挂任何窗口 slot，放条右侧系统区。平时隐身，用量超阈值（暂定 80%）显示百分比，点开看两个窗口详情和重置倒计时。数据来源与 Claude Usage / Vibe Island 同路（用量接口 + transcript 统计）。

分界规则：全局的归全局区，窗口的归窗口 slot。

## 8. 未决问题

- 胶囊向上浮出的视觉干扰度：出现在窗口内容区边缘，是否比预想的烦人？需要动效原型验证（假数据即可）
- 文本层换内容时，格子宽度跟不跟着变：条上的宽度是按标签文本算出来的，状态文字若比歧义标题长，格子会变宽并推挤邻格——那正是第 2 节身份层要保的东西。倾向是状态文字沿用同一条宽度规则、不因状态改变格子宽度，需在骨架落地时定死
- 通用上报协议的具体 schema（session_id、cwd、state、message、progress 起步，等第一个真实接入方再定稿）
- 声波动效 + 封面角标 + 歌名文本同时出现时，音乐 slot 的信息密度是否过载，需原型看效果
- waiting 排队策略：先来后到之外，是否给「要权限」高于「提问」的插队权
- 阈值与默认值（限额 80%、done 未读超时时长）待实际使用调参
